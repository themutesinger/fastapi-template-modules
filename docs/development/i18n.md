# i18n & Error Localization Workflow

This project keeps error responses and other user-facing messages localized without forcing
developers to write raw text in code. The workflow is split into two scripts and a few `make`
targets to keep everything explicit and reproducible.

## Runtime behaviour

- All domain/business errors inherit from `infra.errors.BaseError`.
- Each error defines `code`, `message_key`, `detail_key`, and `status_code`. Response payloads
  are rendered through `translate()` so they are always ready for multi-language support.
- Custom detail strings are accepted; когда их передают вручную, `BaseError`
  пишет предупреждение в лог, чтобы напомнить о переводах и пересмотре контракта.
- `infra/i18n/translator.configure()` is called during app bootstrap using values from
  `Settings` (`I18N_*` variables). If translations are disabled, the system falls back
  to returning the raw keys, which is handy for local development.

## Command pipeline

1. **Collect keys** – `make i18n-register`  
   Parses the source tree, finds subclasses of `BaseError`, and logs their `message_key` /
   `detail_key` into `locales/.i18n_keys.json`.

2. **Refresh translations** – `make i18n-refresh`  
   Generates `locales/i18n_stubs.py` from the registry, runs Babel extraction/update,
   and (re)compiles `.mo` files.

3. **Verify translations** – `make i18n-verify`  
   Simple safety net for CI: fails if any `.po` entry still contains an empty `msgstr`.

All commands honour the `PYTHON` environment variable, so you can use `PYTHON=uv run make …`
or similar wrappers.

## Adding a new error

1. Declare a subclass of `BaseError` with the required keys:
   ```python
   class UserAlreadyExistsError(BaseError):
       code = "unique"
       message_key = "conflict"
       detail_key = "user_exists"
       status_code = 409
   ```
2. Run `make i18n-register`.
3. Run `make i18n-refresh`.
4. Fill in the new entries inside `locales/<lang>/LC_MESSAGES/messages.po`.
5. Optionally run `make i18n-verify` (CI will do it too).

## Settings

Environment variables (defaults shown in `ENV.EXAMPLE.txt`):

| Variable                    | Purpose                                        |
|-----------------------------|------------------------------------------------|
| `I18N_ENABLED`              | Toggle real translations vs raw keys           |
| `I18N_DEFAULT_LOCALE`       | Locale used when none is set                   |
| `I18N_FALLBACK_LOCALE`      | Secondary locale if a translation is missing   |
| `I18N_DOMAIN`               | gettext domain (usually `messages`)            |
| `I18N_LOCALES_DIR`          | Directory where `.po/.mo` files are located    |

All values are available via `Settings` and can be overridden per environment.
